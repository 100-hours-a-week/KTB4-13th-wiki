## 시스템 아키텍처
> (이미지 또는 도식 첨부)

- **검색 서버**: FastAPI. 규칙 파서 → 키워드 + 벡터 하이브리드 → 랭킹. LLM 비의존.
- **추천 서버**: 입력 해석 → 후보 검색 → 추천 이유 생성. 외부 LLM API 사용.
- **데이터 계층**: **AI 전용** PostgreSQL + pgvector. 백엔드와 공유하지 않는다. 커머스 데이터는 BE MySQL → AI Postgres **단방향 복제**로만 들어오고(`v_*` 사본, 읽기 전용), AI가 쓰는 것은 `book_embeddings`·`taste_profile`·`idempotency_records` 셋뿐이다.
- 상세: [서비스 아키텍처 모듈화](서비스-아키텍처-모듈화)

## 컨벤션 룰

브랜치·커밋·PR·머지 규칙은 팀 공통 문서를 따른다.

→ **[팀 컨벤션](팀-컨벤션)**

요약하면 이렇다.

| 항목 | 규칙 |
| --- | --- |
| 브랜치 | `feature|fix|hotfix|refactor|chore|docs/<이슈번호>-<slug>` |
| 커밋 | `<type>: <summary>` · 마침표 없음 · 저장소 이름을 scope로 쓰지 않음 |
| PR | 승인 1명 필수 · 자가 승인 불가 · 400줄 권장 |
| 머지 | **Squash Merge만** · main 직접 push 금지 |

### 코드 스타일 (Python)

팀 공통 문서에는 Java·JS 규칙만 있어 AI 파트 규칙을 여기에 둔다.

| 대상 | 규칙 | 예시 |
| --- | --- | --- |
| 함수·변수 | snake_case | `check_database` |
| 클래스 | PascalCase | `Settings` |
| 상수 | UPPER_SNAKE_CASE | `MAX_BATCH_SIZE` |
| 모듈·파일 | snake_case | `book_embedding.py` |
| 내부 전용 | 앞에 `_` | `_pool` |

- **포매터·린터는 `ruff`를 기준으로 한다.** CI의 Lint 단계가 이것으로 판정한다
- 함수 시그니처에 **타입 힌트를 붙인다.** `pydantic`은 이 타입으로 실제 검증을 수행한다
- 외부 I/O(DB·HTTP)를 하는 함수는 `async def`로 쓴다
- 시각은 항상 **aware datetime**을 쓴다. `datetime.now()`(naive)는 쓰지 않는다

### AI 파트 추가 규칙

- **모델·프롬프트를 바꾸는 PR**에는 Provider, Model ID, Prompt Version, 고정 Dataset 검증 결과, 응답 시간·비용 변화를 적는다
- **벡터 차원이 바뀌는 변경**은 `book_embeddings`·`taste_profile` 전량 재생성이 필요하므로 **단독 배포로 분리**한다
- 스키마 변경은 반드시 `db/migrations/` 파일로 남긴다. 운영 DB 수동 DDL 금지
